# Query cohorts for cadenceworkflow.io Search Console reporting

:::note Internal file, not published

This file lives in `docs/_analytics/` rather than `docs/analytics/`. The docs plugin's default
`exclude` covers `**/_*/**`, so an underscore-prefixed directory is built by nobody and appears in
no sidebar, no route, and no sitemap entry.

The underscore is load-bearing. This repo's sidebar in `sidebars.ts` is explicit rather than
autogenerated, which is easy to mistake for a guarantee that an unlisted file stays private. It is
not. A file placed at `docs/analytics/query-cohorts.md` builds a public page at
`https://cadenceworkflow.io/docs/analytics/query-cohorts` and is listed in `sitemap.xml`, despite
never appearing in a sidebar. Verified by building both ways.

:::

Authoritative cohort specification. Every Search Console report for cadenceworkflow.io uses these
definitions. The regex definitions in this file are authoritative.

The Google Search Console branded-queries filter is not authoritative. It is AI-classified, Google
does not publish the classifier or its version, and its output can change between pulls without
any change in the underlying queries. Use it as a secondary cross-check only, and never as the
source of a reported number. When the filter and these regexes disagree, the regexes win and the
disagreement is worth recording.

## Cohort definitions

All matching is case-insensitive. Evaluate in order: a query is tested against H first, then C,
then P, and anything left is O. The order matters, because P is defined by exclusion.

| Cohort | Name | Definition |
| --- | --- | --- |
| H | Bare name and misspellings | Query matches `^(cadence\|casence\|cadense\|cadance\|cadenc\|cadencd\|cedence\|caddence\|cadene)$` |
| C | Comparison | Query contains `temporal` |
| P | Product | Query contains `cadence` or a listed misspelling, is not H, and is not C |
| O | Other | Everything else |

### The H list is append-only

The variant list in H contains every variant observed in the 28-days-to-18-Aug-2026 export. It is
append-only. New misspellings are added as they appear, each with the date it was added. Variants
are never removed, because removing one silently rewrites history for every prior period.

| Variant | Date added |
| --- | --- |
| cadence | 2026-08-18 |
| casence | 2026-08-18 |
| cadense | 2026-08-18 |
| cadance | 2026-08-18 |
| cadenc | 2026-08-18 |
| cadencd | 2026-08-18 |
| cedence | 2026-08-18 |
| caddence | 2026-08-18 |
| cadene | 2026-08-18 |

Appending a variant to H moves traffic out of P, since P is defined as containing cadence or a
listed misspelling while not being H. Any report spanning an append must say which variants were
added inside the window.

## Methodology

### 1. Anonymized-query gap

Search Console withholds queries that too few users searched, so query-level rows never sum to the
site totals. In the reference export, query-level rows cover 686 of 1,289 clicks and about 130,348
of 203,242 impressions. That is 53.2% of clicks and 64.1% of impressions.

Cohort reporting therefore covers query-visible traffic only. Every report built from these
cohorts must state this explicitly, and must state the query-visible share for its own window
rather than reusing the numbers above. Cohort totals are not site totals and must never be
presented as site totals.

### 2. Weighted position

Average position weighted by impressions:

```
weighted position = sum(position_q * impressions_q) / sum(impressions_q)
```

where `q` ranges over the query-visible rows in the cohort. The unweighted mean of per-query
positions is not used, because it lets a single low-impression query at position 90 move a cohort
average that represents a hundred thousand impressions.

### 3. Monthly pull procedure

1. Open the Search Console performance report for cadenceworkflow.io.
2. Set search type to Web. Other search types are excluded.
3. Set the date range to a 28-day window. Use 28 days rather than a calendar month, so every
   window contains exactly four of each weekday and weekday seasonality cancels.
4. Export the query-level rows, and separately record the report totals for clicks and
   impressions. Both are needed, the totals for the query-visible share and the rows for the
   cohorts.
5. Apply the cohort regexes in the order H, C, P, O. Every query-visible row lands in exactly one
   cohort.
6. Report per cohort: clicks, impressions, CTR, weighted position.
7. Report the query-visible share of totals, for clicks and for impressions separately.
8. Record any variant appended to H during the window, with its date.

### 4. Reading rule for the CDNC-20311 experiment

The cohort H read at deploy timestamp plus 28 days uses the definitions in this file, subject to
the open item recorded above.

Thresholds:

- H CTR at or above 0.4% means the segment is addressable.
- H CTR below 0.25% with position held means brand collision, and the segment is deprioritised.
- Anything between 0.25% and 0.4% is inconclusive, and the test extends.

Cohort P is the guardrail and must not regress.

"Position held" means the H weighted position at the read is not materially worse than the frozen
baseline position of 8.95. The threshold for "materially worse" is FILL IN, and must be fixed
before the read rather than chosen once the number is known.
